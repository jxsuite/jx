# Jx Monorepo — Scripts

Subsystem notes for three things under `scripts/`: the Markdown formatter (`scripts/normalize-markdown.ts`, `scripts/lib/unwrap-prose.ts`), test selection (`scripts/test-affected.ts`, `scripts/lib/test-graph.ts`, `scripts/lib/test-selection.ts`) and the coverage manifest check (`scripts/check-coverage-manifest.ts`). The root `AGENTS.md` holds the rest of the agent notes, and everything in it applies here too.

## Markdown source is not wrapped

- **Markdown source is not wrapped.** The rule is one paragraph per line in every tracked `.md` — `docs/`, `specs/`, every README, the starters, the `AGENTS.md` files. A source-wrapped file fights the editor's own soft wrap, and editing a wrapped paragraph re-flows every line after the edit, so a one-word change arrives as a five-line diff. `bun run format:md` fixes a file. The engine (`scripts/lib/unwrap-prose.ts`) parses with the same remark stack that renders the pages — GFM, frontmatter and directives — and joins line breaks only inside a `paragraph` node, then edits the source by offset rather than re-serialising the tree, so a table, a fence or a `:::` marker is safe by construction rather than by a rule somebody remembered. Oxfmt's `proseWrap` stays `preserve`: its `never` folds a `:::doc-note` marker into the paragraph under it and unpads every table.
- **The rule is dormant, and turning it on is three steps.** The sweep is ~80 files and 6,500 deleted lines, so it conflicts with every open pull request and was deliberately not landed with the tool. `docs:markdown` and the nano-staged `*.md` hook both pass `--no-wrap`, so neither CI nor a commit rewrites anybody's Markdown today. To finish it: run `bun run format:md`, commit the result, and delete `--no-wrap` from the two `package.json` strings that carry it (`scripts.docs:markdown` and `nano-staged["*.md"]`). `specs/README.md` documents the header block and should gain the `\` markers in the same change.
- **A line break that means something is written `\`.** Three survive the pass: a hard break the author wrote (a trailing `\`, or two trailing spaces, which are rewritten to `\` because an invisible break is one an editor silently eats); a **labelled run**, two or more consecutive lines that each open with a bold key, which is what a spec's `**Version:** / **Status:** / **Updated:** / **License:**` header is and which the formatter marks for you; and a line whose whole content is one text directive (`:span[…]{…}`), which is a block in intent and gets no marker, because a `<br>` between two blocks would be a rendering change. Three gates were made wrapping-agnostic ahead of the sweep so it cannot mint releases: `spec-status.ts` reads header values up to the `\`, `spec-bump.ts` preserves the marker on a line it rewrites, and `check-spec-release.ts` unwraps both sides before comparing.

## Test selection (`bun run test:affected`)

`bun run test:affected` runs the tests a diff can fail, and `bun run verify` (lint, the type-aware lint, both typechecks, then `test:affected`) is what Claude Code's Bash guard runs before a `git push`. The root notes say when to run which; this is how the selection is made and where it stops.

- **Two questions, composed.** `decide()` in `scripts/ci/affected.ts` is asked once per changed path for the WORKSPACES it reaches, so a path's reach is exactly what CI's gate says it is. `scripts/lib/test-graph.ts` then follows the import statements under every test file (static imports, a literal `import()` or `require()`, JSON and CSS imports, each workspace's bunfig `preload`) and each reached workspace is narrowed to the tests that reach the path. Selection never adds a workspace the gate did not.
- **Opaque tests always run in a reached workspace.** A test is opaque when it, or a helper it imports from outside any `src/`, reads the filesystem, spawns a process or computes an `import()` specifier (`FS_ACCESS`). It can depend on a file it never imports. `DECLARED_READERS` exempts a helper known to read only data files, and each entry is held to a file that still exists and still matches.
- **Narrowing is refused, and the workspace runs whole,** for: a path the gate fails open on (`GLOBAL`, unclassified); a workspace's `package.json`, `bunfig.toml` or `tsconfig*.json`; a path that reaches the workspace through `EXTRA_EDGES` (the edge exists because no import records it); and any path that is not a node of the graph, such as a fixture, a data file, a spawned entry point, a deleted file or a source file nothing imports yet.
- **A changed test file reaches its own workspace only**: itself, plus the opaque tests beside it. The runner loads it and nothing downstream does.
- **A type-only module selects nothing.** It is erased at run time, so no import of it survives and `tsc` is what judges it.
- **The known hole.** A source module that loads code by a computed specifier (the runtime importing a project's modules, a host loading an extension by name) can pull a changed file into a test that neither imports it nor is opaque. The extensions are covered by their `EXTRA_EDGES` entries. The rest is why this is a signal and CI's whole-workspace run is the gate.
- **No coverage.** A partial run cannot be held to a per-file `coverageThreshold`: a file loaded by three of the thirty tests that exercise it reads as uncovered. `test:affected` has no coverage mode for that reason, and a coverage question is answered by `bun test --isolate --coverage` in the workspace.
- **Why CI's pull-request lane was not moved to it.** Replaying 100 commits on `main`, file-level selection kept 84% of the test files the workspace gate had already chosen, and 87% of studio's. About 400 of studio's 646 test files mount through `tests/harness.ts` and genuinely load most of the application: one was checked against Bun's module cache, 735 modules loaded and every one inside its static closure. For a change to that core, "the tests that load it" is most of them, so moving CI would trade the per-file coverage gate for about a sixth of the files. Locally the saving is larger, 63% of the files a run of every workspace costs over the same commits, because most of it is the workspace gate arriving on the working tree.
- **What would actually shrink it** is the suite, not the selector: a studio test that imports only the module it tests is one this can skip, and one that boots the harness to test a pure function is not. Prefer the first where it suffices.
- `scripts/test-affected.ts` and `scripts/lib/test-*.ts` are unclassified in `affected.ts`, so an edit to them costs a full CI matrix, like any other top-level script.

## The coverage manifest check adjudicates a missing file

`scripts/check-coverage-manifest.ts` fails when a `src/**/*.ts` file never appears in a workspace's `coverage/lcov.info`. The root notes carry the rule for writing tests; this is the defect behind it.

- An absence is evidence, not a verdict: Bun 1.4.0 has been observed leaving a file out of the report that the same run demonstrably loaded and executed. So a missing file is not failed on sight — the script **re-runs coverage over just the tests that name it** and decides from that. Nothing loads it → still a failure, which is the regression the gate is for; it is exercised → the run's counts are held to the workspace's own `coverageThreshold`, so a rescued file stays gated rather than waved through. Naming a module is not loading it, so a `mock.module()` of an otherwise untested file cannot rescue it. If a rescue warning appears for a file **you** just added, the file is fine and Bun is not.
- **That defect has a known shape, and it is not about CI.** Bun 1.4.0 loses a source file's coverage record when **two or more dynamic `import()`s of it are in flight at once**. The module body still evaluates once and its exports work; only the record goes. `Promise.all([import(M), import(M)])` loses it and two sequential `await import(M)` do not, so the discriminator is overlap — not un-awaitedness, not scale, not the runner. `scripts/repro/bun-coverage-drop.sh` demonstrates it in four files with no jx code.
- A dropped file is **absent**, not reported at 0%, so no `coverageThreshold` can fire on it and the aggregate is computed as though it were not there. The manifest check is what stands in front of that, which is why it adjudicates rather than trusting the report.
