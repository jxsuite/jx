# Jx Monorepo — The Rust Core

Subsystem notes for `packages/compiler-binding`: the Cargo workspace that holds the compiler's Rust core, and the npm package that loads it. The root `AGENTS.md` holds the rest of the agent notes, and everything in it applies here too.

Part of the compiler is Rust, loaded as a Node-API addon (`specs/compiler.md` §14). Today that is the image encoder; the plan is for parsing, analysis and emission to follow it, a stage at a time, each one deleting the TypeScript it replaces.

- **The Cargo workspace lives inside `packages/compiler-binding/`, not at the repository root**, and that is load-bearing. release-please releases a component from the commits under its directory and `scripts/ci/affected.ts` retests a workspace from the paths under it, so a root-level `crates/` would release nothing and retest nothing when a codec changed. `Cargo.toml` there says the same.
- **`bun run build:addon` builds it** (`cargo build --release`, then a copy to `packages/compiler-binding/jx-compiler.<triple>.node`, which is gitignored), and `bun run build` runs it first. The dev shell provides `cargo`, `rustc`, `clippy`, `rustfmt` and `nasm`; `rust-toolchain.toml` pins the same Rust for CI, as `.bun-version` pins Bun. Without the addon a build fails on its first image with an error that names this command; a build with no image never loads it.
- **No C library, ever.** Every dependency of a crate is Rust (assembly is fine: rav1e's SIMD kernels are why `nasm` is in the shell). A crate that links a C library brings back the `dlopen` failure sharp had on NixOS, and `cargo tree` plus a `nix build` is how to check. That rule is why WebP is written losslessly: no permissively licensed Rust encoder writes lossy WebP. Check a new crate's licence too: the first pure-Rust lossy WebP encoder found was AGPL.
- **Before finishing a change to a crate**, from `packages/compiler-binding`: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`, then `bun run build` and `bun test --isolate` there, which runs the real addon. The `rust` job in `test.yml` runs the first three.
- **Crates carry no version.** The addon reports the npm package's version, handed to the compiler as `JX_ADDON_VERSION` by the build script. A version in `Cargo.toml` would also live in `Cargo.lock`, and a release that bumped one without the other would break every `--locked` build.
- **Releasing** builds the addon once per platform (`.github/workflows/addon.yml`, eight triples, held to `RELEASE_TRIPLES` by `scripts/addon-lanes.test.ts`), and `scripts/addon-packages.ts` turns the set into `@jxsuite/compiler-binding-<triple>` packages and lists them as `optionalDependencies` of the two packages that run the loader. That list is written at publish time and never committed, because it names versions that do not exist until the release that publishes them. **Each of those nine packages needs an npm trusted publisher before its first release** (`.github/AGENTS.md`).
- **A pull request that touches this package runs the same eight builds** (`addon` in `test.yml`, gated by `ADDON_INPUTS` in `scripts/ci/affected.ts`), and six of them load what they built and encode an image with it (`scripts/probe.ts`; the musl ones inside Alpine). The first release is why: the matrix then lived in `publish.yml`, first ran on the release, and three legs failed with every package held behind them. Two things learned there: a musl addon is linked by `cargo zigbuild` (`build.ts --zig`), because Ubuntu's `musl-gcc` hides the `libgcc_s` every dynamic Rust link asks for; and Windows arm64 builds the AVIF encoder without its assembly (a target-specific dependency in `crates/jx_media/Cargo.toml`), because MSVC cannot assemble it. `darwin-x64` and `win32-arm64-msvc` are built and not run: no runner here executes them.
- **Every suite but this package's and desktop's doubles the addon**, with `packages/compiler/tests/_fake-binding.ts` (`installFakeBinding()` before importing the module under test), so a suite never needs Rust to run. The double keeps the width ladder and writes a file per variant; what an encoder does with pixels is proven here and in the crates.
- **This is the one place the repository is not TypeScript.** Everything outside `crates/` follows the root notes as written.
- **A stage that replaces TypeScript is proven by the conformance harness** (`scripts/conformance/README.md`): `bun run conformance capture` records what a browser does with every project in the tree, and `compare` diffs two recordings. Capture a baseline with the code being replaced before deleting it, run `bun run conformance self` first to see that the harness still repeats itself exactly, and put any difference that has no behaviour behind it in `scripts/conformance/normalize.ts` with its reason.
