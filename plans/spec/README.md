- §18 and CSS Containment 3 (a forward from the `standards.md` census): not applied here. The facts hold: an `@container …` key is not a named breakpoint, so `resolveAtQuery` in `packages/runtime/src/css.ts` returns `null` and `walkAt` emits the key verbatim (§9.2's standard at-rules, §9.6's "passed through verbatim"), Studio's own shell uses a named container that way (`packages/studio/src/surfaces/commandbar.json`, `packages/studio/styles/shell-frame.css`), and there is no `$media`-style alias for a container condition. So `standards.md` §11's "Why not yet" ("`$media` is viewport-only …") is stale, and the likely end state is a **Subset** row here binding §9.2. That row cannot land from this spec alone: `backlog-already-cited` (`scripts/docs/check-standards.ts`) fails while `standards.md` §11 still lists the entry, so the row and the backlog removal (or, instead, a rewritten "Why not yet" naming what is actually absent) go in one pull request that edits both specs. Either outcome is a classified row or a backlog entry, not an open item, so no plan.
- §6.6's `Future` marker and §21.3's closing sentence describe a restricted evaluator that would remove the interpreter's `'unsafe-eval'`; §21.5 declines that removal. `Future` is deferred rather than open, so no plan; reconciling the three sentences is editorial.

## Spec-wide decisions

- **A gap is marked where the behaviour is specified, whichever tier lacks it.** Most open items here are sections the interpreter conforms to and a compiled target (`compile-client.ts`, `compile-element.ts`, the static emitter in `packages/compiler/src/shared.ts`, or the site build's component expansion) does not. Each plan owns its section's gap in every tier; there is no tier-parity plan.
- **A compiled gap another spec's census already owns is required, not rebuilt.** Where a spec.md section is open for work a `compiler.md` or `site-architecture.md` plan claims, the spec.md owner lists that plan in `requires` and does only what remains.
- **A rule both tiers must apply is inlined into generated modules from one runtime export, with a drift test.** Generated modules load without `@jxsuite/runtime`; `attrHelperSource()` (§8.3) is the precedent. The cookie, prop-supply, slot-distribution and observed-attribute plans follow it.
- **Where the code is deliberately different, the spec follows it** (`reconcile`): the optional root `tagName` (§3.1), the `$elements` array (§13.1), one-way prop forwarding (§13.3), extension-registered content classes (§12.1, §12.5), and `jx dev` building site projects (§16.7).
