  - §3: the lowering branch of `resolvePrototypes` (packages/compiler/src/site/prototype-resolver.ts) calls `registry.byName($prototype)` before `imports` is read, so a local class named like a lowering manifest class is shadowed. `plan:extensions/local-imports-precedence`.
  - §7: the declared `mediaType` feeds only the studio's `accept` map (packages/studio/src/files/file-ops.ts) and editor language id (packages/studio/src/canvas/canvas-render.ts); both servers take `Content-Type` from `MEDIA_TYPE_BY_EXTENSION` (packages/schema/src/media-type.ts, used by packages/server/src/server.ts and packages/compiler/src/site/preview-server.ts). `plan:extensions/declared-media-type-responses`.
  - §8.4: `loadProjectSections` (packages/compiler/src/site/project-sections.ts, also the dev server's through packages/server/src/resolve.ts) gates on the key being present, and `buildRuntime` (packages/server/src/jx-mounts.ts) activates every mount. ## Spec-wide decisions

- §6.1 step 5 and §8.1 are one contract stated twice, so one plan owns both anchors, and §6.1 step 1's reconcile rides with it because it shares the anchor. No host locates a manifest through `"jx"`; the catalogue reads it only as the §9.2 hint (`declaresJxField`, packages/server/src/extension-catalog.ts, served by the dev server and desktop), as does scripts/check-extension-catalog.ts.
- §8.4's comparison and §8.6's gating are one missing predicate, so `plan:extensions/empty-section-gating` owns both anchors.
- The §9.1 settings `icon` and the §10 format `icon` share one open rule (what an extension-declared glyph key must name, and what draws when it names nothing) but live on different surfaces and anchors, so they are two plans, `plan:extensions/settings-section-vocabulary` and `plan:extensions/format-icon-hint`, and whichever is detailed first decides the rule.
- §11.1 is the same code change as site-architecture.md §15.2, so one plan, `plan:_shared/db-push-section-owners`, owns both anchors.
- §9's `referenceable` is closed by a registry view and pointer validation (`plan:extensions/referenceable-sections`); the studio's reference controls reading it belong to `plan:relationships/studio-reference-picker`, which names this plan as its prerequisite. The flag already reaches the studio in the extensions payload's `contributions[].project` (packages/compiler/src/site/format-host.ts).
- Mixed dispositions under one anchor (§9.1: drawing `icon` is an implement, the controls list a reconcile, `renderer` implement-or-remove) stay in one plan, since an anchor has one owner; the detail phase records the disposition per part.
