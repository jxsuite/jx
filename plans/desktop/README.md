## Spec-wide decisions

- §6's Active set is built once. `extractReferences` and the active/global partition belong to `plan:desktop/component-scope-sections`; single-file mode (§4.3, §6.1) renders that same set as its flat list rather than deriving its own.
- §6 specifies the scoping of a panel whose home is studio.md §5.4, which states a different rule (`components/` plus `$elements` imports, no Active/Global split). The census keeps the items here, where the roadmap put them; the detail phase decides which spec owns the scoping and makes the other defer to it. The studio census (plans/studio/README.md) lists §5.4 as verified with no marker, but its `components/` rule is not what ships, so this census forwards a marker for it. Once §5.4 is open, it is owned either by a studio stub that `plan:desktop/component-scope-sections` requires, or by that plan moved to `plans/_shared/` with `studio.md#5.4` added to its claims.
- Editorial drift in sections whose status holds (stale paths, counts and names, with no marker to carry them) is owned by `plan:desktop/app-structure-tree` as riders, so that it survives this record's deletion at graduation.
