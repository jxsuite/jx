## Spec-wide decisions

- **A marker whose remainder is mostly a text `reconcile` but partly code keeps one owner, and the code goes to a claim-less `implement` plan that the owner requires.** §3.1 and §3.2 are both shaped that way: the owner rewrites the section to what ships and drops the marker's code sentences once its prerequisites land, and the prerequisites carry the workspaces and the tests.
- **A marker keeps the form it had before the census when its item closes.** A section the census turned from Implemented to Partial gets `> **Status: Implemented.**` back with a one-sentence summary (§3.2 in `plan:schema/project-schema-keys`, §3.4 and §3.5 in `plan:schema/parse-boundary-readers`); a section the census marked for the first time loses the marker (§3.1 and §4 in `plan:schema/generator-inventory`).
- **The pull request that makes a marker sentence false narrows the marker, and the owner deletes what is left.** `plan:schema/build-schema-agreement` drops §3.2's two code sentences and `plan:schema/prototype-property-declarations` §3.1's FormData and Blob clause, each with its own `minor` fragment (so does `plan:spec/request-url-params` for `urlParams`); the owners' texts are written against the narrowed marker.
- **Each §7 row that overstates the code has one plan that fixes it.** WHATWG HTML and CSSOM are rewritten by `plan:schema/generator-inventory`; RFC 7493 and UAX #31 by `plan:schema/parse-boundary-readers`; BCP 47 and RFC 9110 are made true unedited by `plan:schema/build-schema-agreement`, and `plan:schema/project-schema-keys` only lifts their tier. JSON Schema 2020-12 is untouched. Whoever lands second re-pads the table.
- **A property only one built-in prototype reads is declared under `ExternalClassDef.allOf`, as an `if`/`then` on `$prototype` whose `if` carries `required: ["$prototype"]`.** `plan:schema/prototype-property-declarations` (`FormData` `fields`, `Blob` `parts` and `type`) and `plan:spec/request-url-params` (`Request` `urlParams`) share the one array with no edge between them: whichever lands second appends its entry, its test cases and its names to the flat-set bullet's one exception sentence. The flat set itself does not change, and `plan:schema/generator-inventory`, which requires both, documents the result rather than choosing it.
- **The last claim-owning plan to land graduates schema.md.** `plan:schema/generator-inventory`, `plan:schema/project-schema-keys` and `plan:schema/parse-boundary-readers` (its PBR1.3) each carry the same clause: if `bun run plans:status --spec schema` shows its claims as the last open items, it sets the header to Implemented, records its change with an in-place `bun run spec:bump schema.md minor -m "…"` instead of a fragment, and deletes `plans/schema/`. The enabling plans claim nothing and never graduate it.
- **No schema plan waits on whether `jx build` schema-validates.** `plan:spec/expression-build-checks` owns that question; `plan:schema/build-schema-agreement` (the build refuses by construction) and `plan:schema/parse-boundary-readers` (only how `jx validate` reads files changes) are right under either answer, so neither requires it.
