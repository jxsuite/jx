# A site build instantiates every external class a page or component names, at build time or in the browser, with or without an `$implementation`, and fails on one it cannot

## Context

Two sections describe one mechanism, a state entry naming an external class and what a build turns it into, and both are open for the same two refusals, so one plan claims both.

`specs/compiler.md` §3, line 61:

> **Status: Partial.** Two rows do not hold. An external class with `timing: "client"` reaches a compiled page as its literal definition object in reactive state (`compile-client.ts`, and `extractInitialValue` in `compile-element.ts`), never instantiated or resolved, and only a registry class with a `lower` capability compiles to a working definition (`packages/compiler/src/site/prototype-resolver.ts`). An external class with `timing: "compiler"` is baked only when its document names an `$implementation`: `resolveClassPrototype` in the same file refuses a self-contained class with a console warning, and the site build then strips the entry, so nothing is baked and the build reports no error (§5.4). The server-function row's missing client fetch is marked on §6.1. With `build.headers.security.csp` set, the site build emits a Content-Security-Policy naming both constant inline blocks by hash (`packages/compiler/src/site/csp.ts`, `site-architecture.md` §14.3.1), and the page loads nothing from a third party (§12, `site-architecture.md` §8.7).

`specs/compiler.md` §5.4, line 351:

> **Status: Partial.** Only a direct compile of the class document (route 0, §5.6) generates a class from the schema. A state entry naming a class with no `$implementation` gets none in a site build: at `timing: "compiler"`, `resolveClassPrototype` in `packages/compiler/src/site/prototype-resolver.ts` refuses it (`has no $implementation field`, logged as a warning) and the entry is then stripped, and at `timing: "client"` it reaches the page as its literal definition (§3). Only the runtime and the dev server construct one (`classFromSchema` in `packages/runtime/src/runtime.ts` and `packages/server/src/resolve.ts`).

The rows: "External class with `timing: "compiler"` → HTML with baked response data" and "External class with `timing: "client"` → HTML + runtime hydration". Confirmed for the first by a scratch `buildSite` with a `Greeter.class.json` holding no `$implementation`: the build printed `prototype-resolver: failed to resolve "g" ... has no $implementation field`, returned `errors: []`, and `app.js` had no `g` while still binding `${state.g}`. Confirmed for the second by compiling a page holding `{ "$prototype": "Widget", "$src": "./w.class.json", "timing": "client" }`: the module's `reactive({...})` carries that object verbatim.

**What exists** (re-verified)

- `compileClient` (`packages/compiler/src/targets/compile-client.ts`) lowers `LocalStorage`, `SessionStorage`, `Request` and `Cookie`; any other `$prototype` def falls through to `stateEntries.push([key, def])`. `extractInitialValue` (`compile-element.ts`) does the same with `JSON.stringify(def)`.
- `resolvePrototypes` (`prototype-resolver.ts`), called only from `compilePage` in `packages/compiler/src/site/site-build.ts`: a def whose `timing` is set and not `"compiler"` is lowered when its registry class declares `lower` (a failed lower is a `console.warn`) and otherwise skipped; any other def gets `$src` from `imports[$prototype] ?? registry.byName($prototype).classPath` and goes to `resolveClassPrototype`, which throws without `$implementation`, imports it through `importImplementation` (`format-host.ts`), strips `RESERVED_KEYS` (the six keys `spec.md` §12.3 lists), injects `_project` and `_document`, and returns `await instance.resolve()` or the instance. Every throw is a `console.warn`.
- The strip in `compilePage` deletes every state entry still marked `timing: "compiler"` after resolution, resolved or not.
- `compileClassJson` (`packages/compiler/src/targets/compile-class.ts`): the schema-to-class generator, reached only through route 0. Its module has no imports and ends `export default <Title>`.
- The interpreter's contract: `importAndInstantiate`, `resolveClassJson` and `classFromSchema` in `packages/runtime/src/runtime.ts` (reserved keys stripped, `resolve()` then `.value` then the instance, `subscribe`, state awaited before first render); `classFromSchema` in `packages/server/src/resolve.ts`.
- Delivery machinery to reuse: `rewriteSidecarSrc`, `claimAsset` and `sidecarBundles` in `site-build.ts`; `bundleEntry`/`bundleSource`, `CLIENT_EXTERNALS` in `packages/compiler/src/site/bundler.ts`; `sidecarAssetPath` (`@jxsuite/schema/asset-paths`); `BUILT_IN_PROTOTYPES` (`@jxsuite/schema/defs`); `buildInitialScope`'s runtime-only marks for `Request` (`shared.ts`); `attrHelperSource()` as the precedent for a helper inlined into emitted modules.
- Tests: `prototype-resolver.test.ts`, `connector-mounts.test.ts`, `compile-client.test.ts`, `compile-element.test.ts`, `compile-element-render.test.ts` (runs a compiled element in happy-dom), `sidecar-bundler.test.ts`, `no-eval.test.ts`.

**Corrections to the census reading**

1. Components never reach the resolver. `buildSite` compiles each component with `compileElement` and re-reads it for `componentDefs`; neither path calls `resolvePrototypes`. So in a component, a `timing: "compiler"` class is a literal whether or not it names an `$implementation`, and a registry class with `lower` is never lowered either.
2. Constructing a self-contained class is not enough for the reviewer's case: `Greeter` exposes its value through a `value` accessor, and the build resolver skips `.value`, so it would bake the instance. The `resolve()`/`.value`/instance order is part of this work.
3. Per-class bundles would break the flagship classes. `extensions/auth`'s `Session` (`session.ts`, a module-level store) and `AuthActions` (`actions.ts`, which calls `refreshSession` from `session.ts`) both default to `timing: "client"` (`$studio.stateDefaults`); two separate bundles give each its own store, and a sign-in never reaches the `Session` entry.
4. A class whose descriptor references `#/$context/` (`ContentCollection`, `ContentEntry`, `Data`, `Auth`) is sent to the dev proxy by the interpreter because a browser cannot supply that context; a built site has no proxy.
5. `compileClassJson` writes a `$ref` base as `extends <Name>` and imports nothing, so a generated class extending another class document throws a `ReferenceError` on load.

**Related, no edge.** `plan:spec/external-class-contract` and `plan:spec/timing-values-in-built-sites` require this plan (see the integration contract). `plan:extensions/local-imports-precedence` edits the lowering branch of the same loop; `locateClass` below already reads `imports` before the registry. `plan:_shared/compiled-element-lifecycle` and `plan:_shared/compiled-prop-bridge` edit the same `connectedCallback`. `plan:compiler/shared-utilities-signatures` owns `compiler.md` §11's marker, to which this plan adds one entry. `plan:spec/web-api-prototype-parity` owns the built-ins, which `BUILT_IN_PROTOTYPES` keeps out of this path.

## Decisions

- **Decided:** a self-contained class is generated by `compileClassJson` at both timings, not by a port of `classFromSchema`, because shipped code must contain no `new Function` (`compiler.md` §13's ECMA-262 row, `no-eval.test.ts`), §5.4 already says the compiler generates the class, and building from the same module text the browser receives means one class runs at both timings. The generated class keeps `#private` fields (§5.5) where the interpreter uses `_`-prefixed ones; that divergence predates this plan.
- **Decided:** the build resolver reads `.value` between `resolve()` and the instance, in the helper both timings share, because §12.3 orders the three and correction 2 makes it load-bearing here. `plan:spec/external-class-contract`'s `.value` item is delivered by this plan.
- **Decided:** all client class entries of a build are bundled in one bundler call with code splitting, one entry per class at `/assets/class-<Name>.js` (`sidecarAssetPath("class:<Name>")`) plus shared `/assets/chunk-<hash>.js`, because correction 3 needs a module two classes import to be one instance on a page, and one URL per class keeps what a page downloads proportional to the classes it uses. Two classes with one name are a build error through `claimAsset`.
- **Decided:** each entry module default-exports the class: a re-export of `m[name] ?? m.default?.[name]` from the `$implementation`, or the generated class. That is the lookup the interpreter and the build resolver both perform, so the tiers accept the same implementations.
- **Decided:** only an explicit `timing: "client"` is hydrated; an unset `timing` keeps its build-time resolution. What an unset `timing` means is `plan:spec/timing-values-in-built-sites`'s question, and `isClientExternalClass` is the one predicate that answer would widen.
- **Decided:** the browser gets the interpreter's config: the reserved keys stripped, values verbatim, no `_project` or `_document`. One compiler constant, `EXTERNAL_CONFIG_RESERVED` (the six keys `spec.md` §12.3 lists), serves the build resolver and both targets, so `plan:spec/external-class-contract`'s reserved-list item edits one line.
- **Decided:** two shapes are refused with a build error naming the entry: a self-contained class whose `extends` is a `$ref` (correction 5: "give it an `$implementation`"), and a class whose descriptor references `#/$context/` at `timing: "client"` (correction 4: "use `timing: "compiler"`").
- **Decided:** a `resolve()` that rejects in the browser leaves the entry `null` and logs `Jx: external class "<key>" failed` with the error, so one failing class does not stop the rest of the page from hydrating.
- **Open:** does a compiled page or element wait for its classes before its first render? Recommendation: wait, in both targets. The interpreter awaits every class before rendering and Studio's canvas runs the interpreter, so a template such as `${state.forecast.days.length}` works in the editor and would throw on `null` in production if the compiled tier did not; the prerendered HTML stays on screen meanwhile, so the cost is time to interactivity, not a blank page. The alternative, starting at `null` like a compiled `Request`, is simpler to emit and needs a §3 sentence telling authors to guard every read.
- **Open:** does a component's `timing: "compiler"` class resolve at build time, and where does the value go? Recommendation: resolve it once per component file and make the value the component's initial state (`{ "default": value }`), so both the prerender and the shipped module see it, because §3's rows make no page/component distinction, a compiled element renders from its state, and the alternative (refusing compiler timing in components) removes a documented capability. The census missed this (correction 1).
- **Open:** does every entry the build cannot resolve or deliver fail the build? Recommendation: yes, including an unset-timing class whose build-time `resolve()` throws (the message suggests `"timing": "client"`), a failed `lower`, and a `timing: "compiler"` entry whose non-built-in `$prototype` names no class. Each ships today as a page bound to nothing while the build reports success, which is the failure this repository already refuses for unresolvable sidecars and runtime assets; a built-in such as `Request` at compiler timing is left to `plan:spec/timing-values-in-built-sites`. Builds that pass today will fail, which is why this is open.

## Implementation

### Slice CEC1.1: build time

1. New `packages/compiler/src/site/external-class.ts` (header `@docs extending/extensions/classes`):
   - `interface LocatedClass { classJsonPath: string; classDef: JxClassDef; exportName: string }`.
   - `locateClass(def, { docDir, projectRoot, imports, registry }): LocatedClass | undefined`: the descriptor is `def.$src ?? imports[def.$prototype] ?? registry?.byName(def.$prototype)?.classPath`; `undefined` when none. Path resolution and parsing are `resolveClassPrototype`'s steps 1 and 2 moved verbatim (relative against `docDir ?? projectRoot`, otherwise `createRequire(<root>/package.json).resolve`, then `parseClassDef`). `exportName` is `def.$export ?? classDef.title ?? def.$prototype`, as today.
   - `loadClass(located): Promise<ExternalClassCtor>`. With `$implementation`: `importImplementation(resolve(dirname(classJsonPath), $implementation))`, then `mod[name] ?? mod.default?.[name]`, throwing `Module <impl> does not export "<name>"` unless it is a function. Without: refuse a `$ref` `extends` (Decided), `compileClassJson(classDef)`, write it to `join(tmpdir(), "jx-class-<pid>", "<title>-<sha256 prefix>.mjs")`, `import(pathToFileURL(file).href)`, remove the file, return `mod.default`. The content-hashed name makes the module cache safe across pages and rebuilds.
   - `instantiateAndResolve(Ctor, config): Promise<{ value: unknown; instance: object }>`: `new Ctor(config)`, then `await instance.resolve()` when it is a function, else `instance.value` when `"value" in instance`, else the instance.
2. `packages/compiler/src/shared.ts`: `EXTERNAL_CONFIG_RESERVED` (moved from `RESERVED_KEYS` in `prototype-resolver.ts`), `externalClassConfig(def): JsonObject` (the def minus those keys), and `isExternalClassDef(def)` (`isPrototypeDef(def) && !BUILT_IN_PROTOTYPES.includes(def.$prototype)`).
3. `resolvePrototypes` (`prototype-resolver.ts`):
   - returns `Promise<Record<string, JxStateDefinition>>`, the entries it replaced (lowered or resolved), and takes `asInitialValues?: boolean` in `projectContext`;
   - a failed `lower` records a failure instead of warning;
   - otherwise `locateClass`; with no class, a `timing: "compiler"` entry for which `isExternalClassDef` holds records `names no class: give it a $src or an imports entry, or enable the extension that provides "<name>"`, and anything else `continue`s as today;
   - with a class: `loadClass`, the config (`externalClassConfig`, then the existing `basePath`, `_project` and `_document` injection), `instantiateAndResolve`, and the assignment: the raw value plus the `timing` marker on an object, as today, or `{ default: value }` under `asInitialValues`;
   - a throw records `"<key>" ($prototype "<name>"): <message>`, with ` (set "timing": "client" if it must run in the browser)` appended when `timing` is unset;
   - after the loop, any failures throw one `Error` listing every entry, which `buildSite`'s route loop already reports as `Error compiling <route>: …`. `resolveClassPrototype` and `RESERVED_KEYS` are deleted.
4. `compile-element.ts`: `CompileElementOptions.prepareDocument?: (doc: JxDocument, filePath: string | null) => Promise<void>`, awaited in `processElement` right after the document is read and before its `$elements` are walked.
5. `site-build.ts`: `componentResolutions: Map<string, Promise<Record<string, JxStateDefinition>>>` and `prepareComponent(doc, filePath)`. The first call for a path runs `resolvePrototypes(doc, { sourcePath: filePath }, projectRoot, { config, sections, registry, registerBundle, asInitialValues: true })` and stores the promise; later calls assign the stored entries onto the fresh document's `state`, so each component's classes run once per build. Pass it as `prepareDocument` to `compileElement`, and apply it to the document re-read for `componentDefs` before `componentDefs.set`. A failure propagates to the component loop's existing error report.
6. `packages/compiler/bunfig.toml`: add `"**/jx-class-*/**"` to `coveragePathIgnorePatterns`, beside the other transient `/tmp` modules.
7. Spec and docs edits for this slice (below).

### Slice CEC1.2: client timing

1. `bundler.ts`: `bundleEntries(entryPaths: string[], outdir: string, opts: BundleOptions): Promise<string[]>`, one multi-entry build with splitting. Bun: `Bun.build({ entrypoints, splitting: true, outdir, naming: { entry: "[name].[ext]", chunk: "chunk-[hash].[ext]" } })` with the same `define`, `minify`, `external` and `target` `bundleEntry` passes; esbuild: `splitting: true`, `outdir`, `entryNames: "[name]"`, `chunkNames: "chunk-[hash]"`. Returns the files written.
2. `format-host.ts`: export `implementationCandidates(path)` (literal, `src/`→`dist/`, `.js`→`.ts`), used by `importImplementation`, and `implementationFile(path)`, the first candidate that exists.
3. `external-class.ts`: `classEntrySource(located): string`. With `$implementation`: `import * as m from <implementationFile(abs)>; export default m[<name>] ?? m.default?.[<name>];`. Without: `compileClassJson(classDef)` after the same `extends` refusal. Plus `readsBuildContext(classDef)`, true when the descriptor contains `"#/$context/`.
4. `shared.ts`:
   - `isClientExternalClass(def)`: `isExternalClassDef(def) && def.timing === "client"`;
   - `EXTERNAL_CLASS_HELPER = "__jxInstantiate"` and `externalClassHelperSource()`: one inlined async function `(C, name, config)` that throws a `TypeError` naming `name` unless `C` is a function, constructs, resolves in the same order as `instantiateAndResolve`, and returns `[value, instance]`;
   - `emitExternalClassResolution(entries, { statePrefix, instances, indent })`, returning a `Promise.all([...])` expression in which each entry calls the helper with its import binding and config literal, assigns the value through `refAccessor(statePrefix, escapeToken(key))`, records the instance in `instances`, calls `subscribe` when it is a function (assigning each new value the same way), and catches by logging and leaving the entry `null`;
   - `buildInitialScope`: `isClientExternalClass(def)` adds the key to the runtime-only marks, as a `Request` does, so prerender leaves its bindings for hydration.
5. `compileClient`: option `resolveClass?: (def: JxPrototypeDef) => string` (the module URL; the caller binds the document's directory and `imports`). In the `isPrototypeDef` block, a def for which `isClientExternalClass` holds throws `"<key>": external class "<name>" with timing "client" compiles only in a site build` when no resolver is given, and otherwise records `{ key, url, name, config }` and pushes `[key, null]`. `emitClientModule` then emits `import _JxClassN from '<url>';` per distinct URL, the helper, `const _jxInstances = {};`, and `await <resolution>;` immediately before `hydrate(document);` (drop the `await` if the first Open goes the other way).
6. `emitElementModule` gains a trailing `resolveClass?` parameter, and `compileElement` takes `resolveClass?: (def, docDir, imports) => string`, bound per document like `rewriteSrc`. Client class entries initialise to `null` and add the imports and helper at module level; `#jxInstances = new Map()`, `#jxReady = null` and `#jxConnection = 0` in the class. After the property merge, `connectedCallback` runs `this.#jxReady ??= <resolution>; const _c = ++this.#jxConnection; this.#jxReady.then(() => { if (_c === this.#jxConnection && this.isConnected) this.#jxRender(); });`, and the rest of today's body (the `Request` effects, dynamic host styles, slot save, prerender flag, clear and render, slot splice, `onMount`) moves into `#jxRender()`. A document with no client class keeps today's inline body and compiles to a byte-identical module.
7. `compiler.ts`: `CompileOptions.resolveClass?: (def: JxPrototypeDef) => string`, passed to `compileClient` and to `emitElementModule` in route 2.
8. `site-build.ts`: `classEntries: Map<string, { source: string; name: string }>` keyed by asset path, and `deliverClass(def, docDir, imports): string`. It calls `locateClass`, throwing `names no class: …` when there is none, throws for `readsBuildContext`, builds `classEntrySource`, derives `assetPath = sidecarAssetPath("class:" + exportName)`, calls `claimAsset(assetPath, classJsonPath, def.$prototype)`, records the entry and returns `assetPath`. It is passed to `compileElement` as `resolveClass`, and to `compile()` in `compilePage` bound to `dirname(route.sourcePath)` and `layoutDoc.imports ?? {}`. After the sidecar loop, when `classEntries` is non-empty: write each source to `<mkdtemp>/<basename(assetPath)>`, call `bundleEntries(paths, resolve(outDir, "assets"), { external: CLIENT_EXTERNALS, minify, target: "browser" })`, add the returned files to `fileCount`, remove the temp directory, and push `Error bundling external classes: …` on failure.
9. Spec and docs edits for this slice (below).

**Integration contract.** After CEC1.1: `resolvePrototypes` reads `.value`, constructs a self-contained class through `loadClass`, runs for component documents too, and throws one error listing every entry it could not resolve; `external-class.ts` exports `locateClass`, `loadClass` and `instantiateAndResolve`; `shared.ts` exports `EXTERNAL_CONFIG_RESERVED`, `externalClassConfig` and `isExternalClassDef`. `plan:spec/external-class-contract` may rely on these for its `.value` and self-contained items, leaving it the §12.3/§12.4 marker work and the reserved-list edit (one constant); `plan:spec/timing-values-in-built-sites` extends the same failure list to built-ins. After CEC1.2: a `timing: "client"` external class is delivered as `/assets/class-<Name>.js` and resolved by the compiled page or element; instances are held in the page module's `_jxInstances` object and the element's `#jxInstances` map, keyed by state key, which is where a teardown adds `unsubscribe()`; an element with client classes renders through `#jxRender()`, so render-path statements another plan adds go there, and per-connection statements that must precede the render go before the `#jxReady` line; `isClientExternalClass` is the single predicate deciding what hydrates.
