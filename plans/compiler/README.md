## Spec-wide decisions

- **Where compiler.md restates a contract another spec owns, the census marks the drift here and the stub is a `reconcile` that either corrects the restatement or reduces it to a pointer.** The class document belongs to `schema.md` §3.3 and the image pipeline to `site-architecture.md` §9.2; which of the two each stub chooses is a detail-phase decision.
- **A stale restatement is an open item whatever its form.** A table row (§4.3, §5.3), a signature list (§11) and a step's argument list (§7.7) that no longer match the code are marked Partial with a `reconcile` owner alike. Only a worked example (§4.2) and an informative note (§13) ride along editorially with the owner of the section they illustrate.
- **A compiled-output gap is marked on the compiler.md section that specifies the artifact, even when another spec's section is open for the same behaviour, and detailing merges each pair into one `_shared` plan.** The overlaps, all of them:
  - §3 and §5.4 with `spec.md` §12.3 and §12.4 (`plan:spec/external-class-contract`, which already requires `plan:compiler/client-external-class-hydration`) and with `spec.md` §11.3's `"client"` cell (`plan:spec/timing-values-in-built-sites`, which requires it too).
  - §4.1 with `spec.md` §16.4 (`plan:_shared/compiled-element-lifecycle`).
  - §4.4 with `spec.md` §13.2 and §16.2 (`plan:_shared/compiled-prop-bridge`).
  - §6.1 with `spec.md` §11.4 (`plan:_shared/compiled-server-call`).

  - §7.1–§7.7 with `site-architecture.md` §9.2.2, §9.2.3 and §9.2.5 (`plan:_shared/image-pipeline-text`); both are reconciles of one pipeline's prose.
