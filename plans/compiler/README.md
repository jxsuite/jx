## Spec-wide decisions

- **Where compiler.md restates a contract another spec owns, the census marks the drift here and the stub is a `reconcile` that either corrects the restatement or reduces it to a pointer.** Detailing chose one direction for all three, and their Opens are signed together: compiler.md keeps what is about the compiled artifact and points at the owner for the rest. `plan:compiler/class-document-format` points at `schema.md` §3.3 for validity and restates only what route 0 emits; `plan:_shared/image-pipeline-text` moves the pipeline's behaviour into `site-architecture.md` §9.2 and leaves naming paragraphs here; `plan:compiler/shared-utilities-signatures` takes the image entry points out of §11 behind a pointer to §7.2.
- **A stale restatement is an open item whatever its form.** A table row (§4.3, §5.3), a signature list (§11) and a step's argument list (§7.7) that no longer match the code are marked Partial with a `reconcile` owner alike. Only a worked example (§4.2) and an informative note (§13) ride along editorially with the owner of the section they illustrate.
- **A compiled-output gap is marked on the compiler.md section that specifies the artifact, even when another spec's section is open for the same behaviour, and detailing merges each pair into one `_shared` plan.** The overlaps, all of them, as detailing left them:
  - §3 and §5.4 with `spec.md` §12.3 and §12.4 and with `spec.md` §11.3's `"client"` cell. Not merged: `plan:compiler/client-external-class-hydration` is the enabling prerequisite that `plan:spec/external-class-contract` and `plan:spec/timing-values-in-built-sites` require, because their remaining work (runtime teardown, Studio, the build-time `Request`) shares no decision with it.
  - §4.1 with `spec.md` §16.4 (`plan:_shared/compiled-element-lifecycle`).
  - §4.4 with `spec.md` §13.2 and §16.2 (`plan:_shared/compiled-prop-bridge`).
  - §6.1 with `spec.md` §11.4 (`plan:_shared/compiled-server-call`).
  - §6.2 with `site-architecture.md` §15.4 (`plan:_shared/no-adapter-server-tier`, which also rewrites the per-page handler sentence in `spec.md` §11.4's Security Boundary).
  - §6.3 with `site-architecture.md` §14.1.1 (`plan:_shared/page-server-entries`).
  - §7.1–§7.7 with `site-architecture.md` §9.2.2, §9.2.3 and §9.2.5 (`plan:_shared/image-pipeline-text`); both are reconciles of one pipeline's prose.
  - §10's `timing: "compiler"` row with `spec.md` §11.3's `"compiler"` row: `plan:compiler/superseded-ledger-rows` retires the row, and `plan:spec/timing-values-in-built-sites` owns the `Request` it named.
- **The seven plans here require nothing, of each other or elsewhere.** Each was checked against the plans it shares code or text with; none needs another's output to land or to be right. Where two touch one line, the plan that lands second adapts, as the plans concerned say: `compileClassJson`'s `$ref` base and §5.4's "imports nothing" sentence (`plan:compiler/class-document-format`, `plan:compiler/client-external-class-hydration`); the `jx-class-*` coverage pattern in `packages/compiler/bunfig.toml` (the same two); §2's route-4 clause (`plan:compiler/class-document-format`, `plan:_shared/no-adapter-server-tier`); the island path (`plan:compiler/superseded-ledger-rows`, which deletes it, and every plan that mentions it); `docs/framework/build.md`'s "Dynamic pages" section, which `plan:compiler/superseded-ledger-rows` moves while `plan:compiler/client-template-text-children` and `plan:compiler/client-external-class-hydration` each edit a sentence of it; and the emitted `connectedCallback`, whose §4.2 example `plan:compiler/element-binding-table` abridges so that `plan:_shared/compiled-prop-bridge`, `plan:_shared/compiled-element-lifecycle` and `plan:spec/compiled-host-handlers` need neither an edge nor a §4.2 edit (the cross-spec review's proposed edge from it to the first two was checked and not drawn). The edges into this directory run the other way: `plan:_shared/image-pipeline-text` requires `plan:compiler/image-sizes-and-encode-limit`; `plan:spec/external-class-contract` and `plan:spec/timing-values-in-built-sites` require `plan:compiler/client-external-class-hydration`; `plan:spec/shadow-dom-parity` requires `plan:compiler/element-binding-table`. `plans:check` does not scan this record, so each landing pull request rewords this record's mentions of its plan to the section it closed.
- **Marker upkeep: a plan whose code makes a clause of another section's status marker false deletes that clause in its own pull request.** The status word, any cell's status and the section stay the owner's, the owner's plan is re-quoted in the same pull request, and a cell whose only stated reason is closed says so. A marker is the spec's statement of what ships, and a stale clause between two landings is what the census removed. `plan:compiler/image-sizes-and-encode-limit` does this for `compiler.md` §7.2 and `site-architecture.md` §9.2.2; `plan:compiler/client-external-class-hydration` for `spec.md` §11.3, §12.3 and §12.4.
- **§11 has one owner and one entry form.** `plan:compiler/shared-utilities-signatures` owns the marker and sets the form (an H3 holding the export and its parameters in one code span, then a dash and a summary); `plan:compiler/client-external-class-hydration` and the six plans that section's Context lists append entries in that form and touch no marker, and a plan that changes a listed helper's parameters edits its heading.
- **No test here reads `specs/`.** A spec's example or table is pinned by a test carrying a verbatim copy that names the section (`plan:compiler/class-document-format`'s §5.2 example, `plan:compiler/element-binding-table`'s §4.2 input and binding table), and a signature list is pinned by nothing but its call sites (`plan:compiler/shared-utilities-signatures`), because a compiler test reading a spec needs an `EXTRA_EDGES` entry in `scripts/ci/affected.ts` that would rerun the whole compiler suite on every spec edit.
- **The build refuses what it cannot deliver rather than shipping a literal.** `plan:compiler/client-external-class-hydration`'s third Open (every external-class entry the build cannot locate, load, resolve or lower fails it) and `plan:compiler/client-template-text-children`'s raw-text refusal take one stance: a build error naming the entry, where today the page ships bound to nothing and the build reports success. `plan:spec/timing-values-in-built-sites` extends the same failure list, so that Open decides its warnings-or-errors wording too.
