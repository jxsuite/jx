## Spec-wide decisions

- **No edges.** No plan here requires another, and none requires a plan elsewhere: each closes its item in code no other plan here touches (`slugifyHeading`, `contentAssetMounts`, `loadContentType`'s post-load pass), and the plans elsewhere that share those files are textual neighbours (below), so they land in any order. parser.md's fourth open item, §7, is slice CDE1.1 of `plan:_shared/collection-directive-elements`.
- **Graduation.** The pull request that closes parser.md's last open item, whichever of the three plans or CDE1.1 it is, graduates the spec: header `**Status:** Implemented`, `bun run spec:bump parser.md minor` in place with its fragment sentence as `-m` and no fragment (minor, because it rides on an `implement`), and `plans/parser/` deleted. Otherwise each lands its own `minor` fragment and edits only its own line of this record.
- **`plan:parser/uniform-entry-dates` owns `loadContentType`'s tail.** Its `finishEntries` is the one step every branch ends with, so a per-entry step all branches share (CDE1.2's `$elements` stamp) goes there rather than into three branches, and a per-field check added to `validateEntries` (`plan:relationships/reference-validation`) goes first after the `value == null` skip, since the date branch goes. Whichever lands second adapts. The parser plans' other neighbours in `content-loader.ts` are separate functions with no ordering: `contentAssetMounts` (`plan:parser/localized-mount-name-warning`), `rewriteEntryAssets` (`plan:site-architecture/entry-editor-widgets`), `resolveContentTypeRefs` (`plan:relationships/cross-domain-references`, `plan:relationships/reference-validation`) and `Content.projectData` (`plan:site-architecture/build-excludes-drafts`).
- **§10 is edited by row.** `plan:parser/heading-slug-combining-marks` owns the UAX #15 note and `plan:parser/uniform-entry-dates` the RFC 3339 evidence; outside this directory `plan:extensions/declared-media-type-responses` owns the RFC 7763 and RFC 9512 rows, `plan:jx-markdown/commonmark-coverage` the CommonMark and GFM notes, and `plan:standards/citable-community-specifications` the paragraph above the table. A conflict between them is column padding only: keep every row's text and run `bun run format`.
- **`docs/framework/site/content-collections.md`** is edited by all three plans at separate places (the heading-anchor paragraph, the collection-images paragraph, the Dates section and the frontmatter lists), so it conflicts only textually.
