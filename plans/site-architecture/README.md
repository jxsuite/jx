## Spec-wide decisions

- Examples that no longer match the shipped authoring shape for head material (a `$head` of `{ tagName, attributes }` plus a top-level `title`, and a layout that is body content) are one decision, so `plan:site-architecture/head-and-layout-shape` owns §3, §5.1, §5.2, §8.1, §8.2, §8.3 and §8.5 together. One decision is not split between markers and ride-alongs: every section whose example or rule carries the divergence leads with Partial, including §8.5, where the dropped top-level `type` turns a JSON-LD block into script.
- A divergence earns its section a marker; only incidental wording in a section no plan claims rides with the plan whose subject it is: §7.1 with `plan:site-architecture/library-collection-views`, §7.3 with `plan:site-architecture/entry-editor-widgets`, §3.2's "read-only" parenthetical and §10.1's "Site `state` (read-only)" cell with `plan:site-architecture/site-state-scope`, §13.1 and §13.4 with `plan:site-architecture/locale-negotiation-gaps`, §12.1's "else per-route _server.js" pipeline line with `plan:_shared/no-adapter-server-tier`. A divergence inside a section some plan claims belongs to that section's owner, which is why §14.1.1's step 5 and its undocumented `build.deploy` key are `plan:_shared/page-server-entries`'s, and §14.1's `_redirects` row sits under its own marker with `plan:site-architecture/build-output-prose`.
- Where another plan makes the decision a claimed section needs, the owner requires it rather than sharing the claim: `plan:site-architecture/page-context-props` requires `plan:site-architecture/site-state-scope` (which rewrites §5.5's `$site.state` row with §10.4 item 1) and `plan:site-architecture/locale-negotiation-gaps` (whose `*` fix decides whether `$site.locales` is default-first), and `plan:_shared/image-pipeline-text` requires `plan:compiler/image-sizes-and-encode-limit`, which builds the four-encode cap that §9.2.2 and compiler.md §7.2 both state, and `plan:_shared/no-adapter-server-tier` requires `plan:_shared/no-adapter-server-tier`, which makes the per-page `_server.js` that §15.4 and compiler.md §6.2 both describe loadable from `dist/`.
- Two items here are one code change with an item another census already owns: §15.2 with extensions.md §11.1, and §14.1.1 with compiler.md §6.3 (`plan:_shared/page-server-entries`). Each pair belongs in one plan under `plans/_shared/` claiming both anchors. The first pair is merged: `plan:_shared/db-push-section-owners` owns §15.2 and extensions.md §11.1. For the second, the census could write only this directory, so the merge is left to the detail phase and `plan:_shared/page-server-entries` must not become a second implementation. The image prose in `plan:_shared/image-pipeline-text` restates compiler.md §7, whose census marked and planned §7.2 and §7.5 but left §7.3 (the same absent raster allowlist as §9.2.3) unmarked and unclaimed.
