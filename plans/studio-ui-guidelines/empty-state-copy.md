# Every empty region says what it is for, and a disabled empty-state action says why

## Context

## Decisions

- **Open:** which regions §11.1 binds. Recommendation: every `[part="empty"]` block and every `emptyState()` caller, full or inline, plus the three "it's gone" states; a result (a filter or search that matched nothing, a load in progress, a failure, a remote listing that came back empty, a verdict, including a derived pane's reason for drawing nothing) is exempt, and §11.1 says so. Because §11.2 already specifies the inline form, §10's checklist names the noun-phrase shape without exempting inline lists, and the alternative (only the two the marker names) would graduate §11 with six inline lists still saying "No …".
- **Open:** the new sentences. Recommendation: land them as the table under Implementation gives them; review may reword within rule 1 (what the region is for), rule 3 (one sentence per requirement: `doc-header.json`'s line and `panel-page.json`'s both describe custom head tags) and §11.3 (plain words, so no "registered" and no "document position"). Where a section's own description sits directly above its list (the Contexts groups' `desc`, the Locales and Google Fonts section descriptions), that description already says what the list is for, so the table's line says what holds until the first one is added rather than restating it.
- **Open:** `openPageAction()`. `plan:studio-ui-guidelines/git-panel-action-list` hands its label to §11: it opens Quick Access directly, the behaviour of `palette.openFiles` ("Go to File…", ⌘P), under its own label "Open a page…". Recommendation: keep the closure and the label, and say in rule 2 that the record-built rule covers an action that runs a command. Rule 2 asks for a label naming the outcome and gives "Go to the Data panel" as the wrong shape, it can never be disabled, and its six call sites in four modules (`left-panel.ts`, `properties-panel.ts`, `events-panel.ts`, `style-panel.ts`) keep their text. The alternative, `commandEmptyAction(registry, "palette.openFiles")`, prints ⌘P but relabels every no-document state "Go to File…".
- **Open:** §11.2's "same markup". Recommendation: reconcile the text to "the same shape": the container is `part="empty"` (its `data-compact` or a `*-empty` part marks the inline form), the sentence comes first, a disabled control binds `hint`; the child parts in the table are `empty-state.json`'s. Normalizing instead would re-part the children of some 20 empty-region blocks, parts that tests and each document's own style block address, with nothing a reader would see.
- **Decided:** `EmptyStateAction` becomes a union, `{ label; run; chord? }` with either `disabled?: false` or `disabled: true; requires: string`, so a disabled action without its reason does not type-check. `requires` is the registry's noun phrase ("an open project"), and the button's `hint` takes two of the three shapes `commandTooltip` (`src/surfaces/commandbar.ts`, or `src/commands/projection.ts` once `plan:studio-ui-guidelines/git-panel-action-list` GPA1.1 has moved it) builds: `<label> — requires <requires>` while disabled, `<label> (<chord>)` when enabled with a chord. The third, the bare title, becomes empty, because an empty-state button prints its label and a tooltip repeating it is noise (the rule `plan:studio-ui-guidelines/conventions-checklist-controls` states for a kit button that prints its label). A disabled empty-state button then reads like every other disabled command.
- **Decided:** no edge to `plan:studio-ui-guidelines/git-panel-action-list`, whose GPA1.1 adds `commandControl()` in `src/commands/projection.ts`, the same record-to-control projection for the Source Control panel. `commandEmptyAction` needs the raw chord and `requires` as well as the formatted hint, and the two share only five registry calls, so neither blocks the other; whichever lands second may build one on the other. `projection.ts` stays the owner of what a record prints (the audit record's Spec-wide decisions); the one deliberate difference is the enabled, chordless hint, empty here because an empty-state button prints its label, which §11.2 states.
- **Decided:** an action that runs a command is built by `commandEmptyAction(registry, id, options)`: the record's title as label, `keymap.formatBinding(id)` as chord, `disabledReason(id)` as `requires` while `isEnabled(id)` is false, and `run` through `runReported`. It returns `null` (the caller omits the button) when there is no registry, no record, or the record's `when` fails, because that is the registry's own split: a `when` that fails means the capability is absent, an `enablement` that fails means disabled and explained (§12.3). Consequence: the Languages panel's settings button is absent, not dead, when nothing registers `settings.open`, and `pane.pin`'s button would carry the record's reason if it were ever refused (in the app `held` implies a pinnable companion, so only a unit test reaches that branch).
- **Decided:** a test sweeps the documents rather than a `scripts/` gate: it is one file, it runs in the workspace whose documents it reads, and copy a module writes into a template is held by that module's own suite instead.
- **Decided:** the Files panel's `none` and `welcome` cases become one `empty` case with a detail line (empty with no project; the not-a-site sentence for a monorepo root) and one `project.open` button drawn from the record, because both states want the same thing and rule 3 says they must not read as two requirements.
- **Decided:** the git panel's two no-repository buttons get their busy reason here (a `busyReason` projection bound as `hint`) instead of this plan requiring `plan:studio-ui-guidelines/git-panel-action-list`, which redraws those buttons from their records: the sweep makes either landing order safe, and this plan stays unblocked. The sentence takes the "Wait for … to finish" shape `plan:studio-ui-guidelines/conventions-checklist-controls` recommends for busy controls, and the field is the one that plan's CCO2.3 reuses for the other seven `busy`-bound git controls, which are not empty-state actions.
- **Decided:** where `plan:studio-ui-guidelines/conventions-checklist-controls` has landed first, this plan deletes `empty-state.json#empty-action` from `DISABLED_ALLOWANCES` in `tests/control-semantics.test.ts` (its both-ways check fails once the site binds `hint`), and the sweep here drops its disabled-control case, which that test's `disabledReason` rule already holds for every document. `plan:studio-ui-guidelines/conventions-checklist` reads "no allowance left" as part of this plan's landing.
- **Decided:** the Bottom dock keeps its fallback and rewords it, because a region with no object to show never paints a bare container, and a test gating the three records makes the branch reachable.
- **Decided:** the dead `.empty-state*` rules are deleted in this pull request, under the audit record's rule that dead rules go in the pull request that stops the spec naming them.

## Tests

**`packages/studio`** (`bun test --isolate --coverage` from `packages/studio`).

New `tests/empty-state-copy.test.ts`, which reads `src/surfaces/*.json` with `readFileSync` and imports nothing from `src`. An empty block is a node whose `attributes.part` is `empty` or ends in `-empty`; its first sentence is the first string `textContent` under it, in document order through `children`, `map` and `$switch` cases, that is not a lone `${…}` template. `ABSENCE` is `/^(?:No|Nothing)\b|\bthere is nothing\b|\b(?:has|have) no\b/i`. `RESULTS` is a map from `<file><case path>` (`add-repo.json/empty-filter`, `target-line.json/true/empty`) to a one-line reason, holding the ten results under Context.

- "every empty block opens with what the region is for": no block outside `RESULTS` has a first sentence matching `ABSENCE`; the failure lists file, case path and sentence.
- "the results list names only blocks that still read as results": every `RESULTS` key exists and its sentence still matches `ABSENCE`, so the list only shrinks.
- "a control an empty block disables says why": every node inside an empty block whose `$props.disabled` is present and not literally `false` also has `$props.hint` or `attributes.hint`. Left out when `tests/control-semantics.test.ts` exists (Decisions).
- "the sweep sees what it is for": inline fixtures, a block reading "No project loaded" and (with the case above) a disabled `jx-button` with no `hint`, are each reported, and a `${state.x}`-only block is skipped.
